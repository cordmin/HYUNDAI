# L7 등하교 대화 음원 제작

## 새 키 재시도 기록 (2026-11-03)

사용자가 제공한 새 키를 저장소 밖의 사용자 로컬 파일에 보관하고 기존 환경 키를 이 실행에서 제외한 뒤 누락분을 재시도했다. 첫 요청 `s_13`에서 다시 일일 TTS 한도 HTTP429가 반환되어 즉시 중단했다. 새로 생성된 파일은0개이고 현재 결과는72/141개·누락69개로 동일하다. 키 값은 문서·시트·로그·Git에 넣지 않았다.

[Google 공식 안내](https://aistudio.google.com/docs/rate-limits)에 따르면 한도는 API키가 아닌 프로젝트 단위다. 두 키가 같은 프로젝트인지 확인하지 못했으므로 이번 실패가 같은 프로젝트 때문이라고 단정하지 않는다. 공식 안내의 일일 한도 초기화 기준은 태평양 시간 자정이며, 계정의 실제 가용 한도는 별도 확인이 필요하다.

새 키로 다시 실행할 때는 아래처럼 이 프로세스의 키 파일 경로를 지정한다. 값 자체는 출력하지 않는다.

```powershell
$env:DAIT_GEMINI_KEY_FILE = Join-Path $env:USERPROFILE '.dait/gemini-tts-l7-key.txt'
Remove-Item Env:GEMINI_API_KEY -ErrorAction SilentlyContinue
python team/a/voice/rules_tts.py
```

2026-11-03 사용자 지시로 시작했다. **72/141개 생성·기술 검사·부분 납품, 69개 미생성**이다. `s_13` 생성 시 Gemini TTS가 일일 요청 한도(HTTP429)를 반환해 기존 도구의 중단 규칙에 따라 멈췄다. 일일 한도 오류 뒤 추가 API 호출은 하지 않았다. 현재 백그라운드 생성 작업은 없다. 완료율을 높이기 위해 미제작분을 완료로 표시하지 않는다.

완성: 교사 규칙 대사42개·짧은 응답1개·이어 붙이는 말17개·과목 이름12개, 합계72개. 남음: `s_13`~`s_45` 33개와 `n_1`~`n_30`, `n_35`, `n_40`, `n_45`, `n_50`, `n_55`, `n_60` 36개, 합계69개. 정확한 목록은 `delivery/rules/missing.csv`와 `report.json`에 있다. 요청이 다시 허용된 뒤 아래 생성 명령을 실행하면 같은 대본의72개를 재사용하고 빠진69개만 생성한다. 한도 초기화 시각은 확인되지 않았다.

부분 납품 ZIP은 `team/a/voice/delivery/L7-rules-partial.zip`이다. 완료된72개만 담았고 생성하지 않은 파일이나 임시 음성을 끼워 넣지 않았다. L7·B05는 진행 중이며 사람 청취·앱 통합도 후속이다.

## 기준

- 최신 `origin/team-base`의 `1b4dd20a9ba42ef183b60190f7f67f3cdca81d3b`, `voice/규칙-대본.csv` 141줄을 `team/a/voice/rules-script.csv`로 고정했다. 원본 해시와 커밋은 `rules-source.json`에 있다.
- 현재 체크아웃의 이전 숫자 대본 대신 한글로 바뀐 최신 대본을 사용한다. 예: `n_15`는 「십오 분」이다. 대사를 새로 쓰거나 앱의 규칙을 바꾸지 않았다.
- 교사 규칙 대사42개, 짧은 응답1개, 이어 붙이는 말17개, 과목 이름45개, 남은 시간36개로 합계141개다. 짧은 응답도 r로 시작하는 이름이라 r 그룹을 세면43개다.
- 기존 Nika 모델·스타일·인증키 조회·요청 간격·생성 잠금·재시도·해시 재사용·이전 테이크 보존을 재사용한다. 키를 결과물에 넣지 않는다.

## 실행과 결과 위치

```powershell
python team/a/voice/rules_tts.py
# API 호출 없이 현재 대본과 생성본 확인·납품 경로로 내보내기
python team/a/voice/rules_tts.py --check-only
```

- 원본 WAV·생성 메타데이터: `team/a/voice/delivery/rules/raw/nika/`
- 납품 WAV·파일별 영수증: `team/a/voice/delivery/rules/nika/`
- 검사표: `team/a/voice/delivery/rules/report.json`
- 기준 대본과 다른 음원, 누락 음원은 납품 대상에서 제외하고 보고한다. 완료되지 않은 테이크는 성공으로 세지 않는다.

## 검사와 후속

각 WAV의 원본 지문·SHA256·PCM16/mono·길이·비무음을 확인한다. 납품 WAV는24,000Hz로 맞추며 변환 시 전후 길이 차이를 확인한다. `test_rules_tts.py`는 실제 API 호출 없이 숫자 대본 고정,48,000→24,000Hz 변환, 구버전 음원 차단을 검사한다. 테스트의 인공 음원은 임시 폴더에만 만든다.

사람이 직접 들어 발음·억양·이어 붙이는 경계를 판단하는 단계는 사용자 결정에 따른 후속이며, 기술 검사를 청취 승인으로 표시하지 않는다. 앱 담당이 납품 nika 폴더의141개 WAV를 `android/app/src/main/assets/voices/nika/`에 넣고 빌드하면 기존 규칙 빌드 도구가 임시 음성 대신 해당 파일을 선택한다. 실제 앱 통합·빌드는 이 작업에서 대신 수행하지 않는다. 대본이 바뀌면 해당 파일을 다시 만든다.

현재 브랜치는 `codex/taeyeol-tasks`이며 이번 제작 변경은 로컬 미커밋·미푸시다. 공유 시트의 L7·B05에 생성 결과·검사·남은 단계를 구분해 기록한다. 일일 한도가 남은 유일한 생성 장애이며 자동 재개 작업은 설정하지 않았다.
