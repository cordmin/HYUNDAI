# 대화형 시연 v3

2026-10-30. 설정 메뉴에서 음원을 고르는 방식 대신 시작→질문 재생→음성 입력→답에 따른 응답으로 변경했다.

## 화면

- 첫 화면은 등교 준비·하교 대화 두 진입점. 좌측 상단 앱명·소개 문단·캐릭터·진행 단계·학교 안내 메뉴 제거.
- 질문 화면은 질문 하나, 인식 상태, 짧은 답 선택지와 멈추기/말하기. 뒤로 가면 대화와 마이크 종료.
- 모든 조작 아이콘과 런처 아이콘은 Lucide 원본 SVG를 Android vector로 변환해 사용. 원본·라이선스는 design/lucide, APK에도 라이선스 포함.
- Cruz/Nika는 상단에서 바로 전환. 전환 후 자동 재생/녹음하지 않는다.

## 실제 동작 범위

- Vosk small Korean 0.22를 앱에 포함. 기기 내 한국어 음성 인식이며 서버 업로드 없음. 녹음 파일·인식 문장 저장 없음.
- 등교: 준비 여부의 긍정/부정 응답 → 기대되는 수업 → 체육이면 인사, 과학이면 궁금한 것 하나를 듣고 인사.
- 하교: 하루의 이야기를 듣고 중립적인 추가 발화를 권한 뒤 가족 대화로 넘김. 실제 수업 내용이나 감정을 임의로 만들어 응답하지 않음. 자유 대화 AI의 내용 이해를 주장하지 않는다.
- 그만/쉬고 싶어/말하기 싫어는 종료, 다시 말해줘는 같은 질문 반복.
- 제한된 질문에서는 문맥 후보와 범용 인식 결과를 대조해, 관계없는 문장을 억지로 선택지에 맞추는 오류를 줄임. 하교의 열린 답은 특정 활동으로 강제 분류하지 않음.
- 질문 종료 뒤 최대 10초 입력. 잠정 인식 결과만 남은 시간 초과·무음·미지원 답은 다음 단계로 진행하지 않음. 재질문 음원 뒤에는 자동으로 마이크를 다시 열지 않음.
- 기존 CarUxRestrictions·오디오 포커스·lifecycle 중단 유지. 제한 해제 뒤 자동 재개 없음.
- 학교 데이터는 예시. NEIS/내비/Gleo/자유 대화 LLM 연결은 미구현.

## 검증 결과

- assembleDebug / assembleDebugAndroidTest / testDebugUnitTest / lintDebug 성공. 단위 테스트 6개, 실패 0. lint No issues found.
- Pleos 실제 Vosk 엔진에 합성 한국어 PCM을 넣어 준비 완료·미준비·과학·하교 후속·쉬기·미지원 문장 거부 6개 경로와 무음 검사 통과.
- 이 결과는 의미 분기와 입력 경로 검사이며 정확한 받아쓰기 6/6이라는 뜻이 아니다. 특히 열린 문장 받아쓰기는 부정확할 수 있다. 긴 자유 발화·차량 소음·아동 실발화 품질은 검증하지 않았다.
- UI에서 모드 시작 직후 질문 재생·마이크 열림, 짧은 답 버튼의 다음 질문 진입을 확인. 마지막 화면 조작은 사용자 직접 입력이 감지돼 중단함. 사용자 실발화를 합성 파일 검사 결과와 혼동하지 않음.
- 마이크 입력은 실제 AudioRecord를 사용하며 늦은 콜백이 취소된 질문을 진행시키지 않도록 세션 번호로 거부.
- APK 내 음원 102개 및 모델 포함, API 키 미포함 검사 통과. 신규 질문·긍정·부정 3개 대사 × 두 목소리 = 6개 생성.
- 추가 8개 대사 × 두 목소리는 Gemini TTS 일일 요청 한도 100회 오류로 중단해 voice/pending-dialogue.json에 기록. 미완성 음원은 앱에서 참조하지 않음.
- 음성 작업실 서버 자동 재시작은 자동 승인 검토에서 차단되어 수행하지 않았다. 기존 실행 중 서버는 업데이트 전 Python 코드를 사용할 수 있다. 다음에 사용자가 정상적으로 재실행하면 새 오류 처리 코드가 적용된다.
