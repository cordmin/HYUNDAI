# 진주 목록 설정과 하위 화면

2026-11-10 사용자 선택 「진주 목록」을 로컬 앱에 적용했다. 재생 설정·재생목록·앱 색상도 같은 배색과 둥근 조작부로 정리했다. 기준 main 1940974, 이전 버튼·하단 카드·기록 정리 변경은 그대로 유지한다. 이번 커밋·푸시·APK 재빌드·기기 설치는 하지 않았다.

## 반영

- 설정: 세 메뉴를 한 장의 진주색 목록으로 묶고, 원형 아이콘·보조 설명·진입 화살표를 배치했다. 이어서 듣기 토글은 아래에 분리했다. 키보드로 토글한 뒤에도 해당 조작부에 초점이 남는다.
- 재생 설정: 뒤로·앞으로·배속을 같은 묶음 안에 배치했다. 선택된 값은 강조색의 둥근 버튼으로 표시한다. 직접 입력·숫자 검증·저장 동작은 유지한다.
- 재생목록: 순번·수업명·과목을 정리하고, 위·아래·삭제를 원형 버튼으로 맞췄다. 비어 있을 때도 같은 목록 안에 안내한다. 순서 변경·삭제 즉시 저장, 선택 수업 재생, 주행 제한은 유지한다.
- 앱 색상: 라이트/다크 선택 → 배경 미리보기 → 이름 있는 색 조합 세 가지를 먼저 보여 준다. 선택된 조합은 테두리와 aria-pressed로 표시한다. 직접 색 고르기를 펼치면 기존 색상판·색조·시작/끝 색·상세 코드 입력을 쓸 수 있다. 두 모드의 독립 저장과 취소 시 복원을 유지한다.
- 세 하위 화면에 설정으로 돌아가기 버튼을 두었다. 설정 외의 수업 순서 안내창에는 추가하지 않았다.
- 기존 사용자 배색·자동 대비·44px 이상의 주요 조작 영역을 유지한다. 작은 화면에서도 색상 화면의 저장 버튼이 기본 상태에서 잘리지 않게 여백을 조정했다.

## 검사

- 기존 Node 화면·재생 시험 **178개 통과**, JS 문법·`git diff --check` 통과.
- Chromium 실동작: 직접 입력 45초/앞으로 60초/1.5배속 저장, 0초 차단, 재생목록 순서 변경·삭제, 라이트/다크 색 조합·코드 저장, 잘못된 색상 코드 차단, 닫기로 변경 취소, 주행 중 설정·재생목록 진입 차단 통과.
- 설정·재생 설정·재생목록·앱 색상의 4화면 × 665×420·1000×632·420×640 × 라이트·다크 = **24개 렌더** 확인. 가로 넘침 없음, 창이 화면 밖으로 벗어나지 않음, 자동 측정된 보이는 문구 대비 4.5 이상, 브라우저 실행 오류 없음.
- 화면을 직접 대조하며 작은 화면의 저장 버튼 잘림, 앞으로 이동 제목 줄바꿈, 큰 화면의 목록 조작 버튼 타원 문제를 수정했다.
- 검사 결과와 화면: `design/screens/pearl-settings-20261110/checks.json`, 같은 폴더의 화면별 PNG.
- 브라우저 검사는 별도 저장소를 사용했다. 사용자의 실제 배색·재생목록·재생 설정은 시험값으로 덮어쓰지 않았다.

파일: `android/app/src/main/assets/dait-appearance.js`, `dait-queue-ui.js`, `dait-pearl.css`, `dait-preview.html`.

상태: 로컬 앱 반영 완료. 최종 APK·기기 확인은 기존 S5/S9 범위를 유지한다.

## 후속 수정: 앱 영역과 시안 색상

사용자 지적에 따라 창 경계를 추가 검사했다. 기존 native dialog의 top layer는 브라우저 전체를 기준으로 배치되어, 앱이 일부 영역만 차지하면 앱보다 커질 수 있었다. 이제 앱 요소의 실제 위치·폭·높이를 읽어 모달의 inset·최대 폭·최대 높이를 제한한다. 앱 크기 변경은 ResizeObserver로 반영한다. 짧고 좁은 화면의 간격도 viewport 대신 앱 컨테이너 크기로 고른다. 기본 브라우저 backdrop은 투명하게 하고 앱 요소 안의 별도 가림막만 어둡게 처리한다. 닫으면 가림막도 제거한다.

또한 자동 대비 보정이 모달 바탕을 옅은 회색으로 덮어 시안과 달라지는 것을 확인했다. 기본 로즈의 설정과 하위 화면에는 시안의 불투명 색을 사용한다: 바탕 `#f8edef`, 목록 `#fcf6f7`, 구분선 `#e5cdd6`, soft `#f0e1e6`. 기본 다크 로즈도 시안 값을 따른다. 기본 로즈 모달에서는 바탕을 바꾸지 않고 글자 대비를 보정한다. 사용자가 고른 다른 배경은 기존 자동 배색·대비 보정을 유지한다.

추가 검사: 1400×900 브라우저 안에 665×420·420×640·1000×632 앱을 각각 띄우고 4화면, 총12개에서 모달·가림막이 앱 경계 안에 있음과 정확한 시안색을 확인했다. 모달을 열어 둔 채 앱을500×400으로 바꿔도 안에 머문다. 모든 닫기 후 가림막 제거 확인. 기존24개 라이트/다크 렌더·실동작·178개 시험·diff검사도 다시 통과했다. 결과는 같은 스크린샷 폴더의 `app-bounds-and-rose-checks.json`, `app-bounds-and-rose.png`에 있다. 로컬 수정이며 APK 재빌드·기기 검사는 하지 않았다.
