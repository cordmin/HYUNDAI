# 음악: 같은 네 박인데, 왜 느낌이 달라질까?

2026-11-06 사용자 요청으로 제작. 대본 29조각을 기존 Gemini TTS 모델·Nika 목소리로 생성하고, 직접 합성한 리듬 예시와 발문 대기 시간을 편집했다. 사람 교사 검수·사람 청취·앱 통합 전이다.

| 사용 가능한 시간 | 완성 파일 | 실제 재생 길이 | 조각 |
|---|---|---|---|
| 8분 | [rhythm-8min.m4a](rhythm-8min.m4a) | 7분 26.14초 | 11개 |
| 15분 | [rhythm-15min.m4a](rhythm-15min.m4a) | 14분 59.18초 | 19개 |
| 20분 | [rhythm-20min.m4a](rhythm-20min.m4a) | 19분 52.46초 | 25개 |

시간은 상한이다. 긴 무음이나 속도 변경으로 정확한 분 수를 채우지 않았다. 15분판에는 박·템포 비교, 긴 소리와 쉼 비교를 보태고, 20분판에는 강세와 소리 재료 비교를 더했다. 각 판의 CSV에는 실제 순서·화면 문장·전체 대사·발문 대기·조각 길이가 있다. 음원 전체에는 내레이션, 리듬 예시, 질문 대기가 이미 포함되어 있으므로 앱에 넣을 때 대기 시간을 다시 더하지 않는다.

`raw/nika/`는 대사별 원본 WAV와 생성 메타데이터 29쌍이다. 합성 리듬은 이 원본에 들어 있지 않으며 제작기가 최종 파일에 붙인다. 원본의 모델·대본·해시·지문으로 같은 대사의 중복 API 호출을 피한다. 완성판 WAV는 로컬에 보존하고 Git에서는 제외한다. 이전의 잘못 생성된 정리 음원은 takes에 보존되며 납품·Git에서 제외한다.

## 다시 만들기와 검사

저장소 루트에서 다음을 실행한다.

```powershell
python team/a/voice/music_tts.py --check-only
python team/a/voice/music_tts.py --export-only
# 대본을 바꾼 경우, 바뀐 조각만 TTS 재생성
python team/a/voice/music_tts.py
```

검사 결과: CSV 열 수·29개 ID·대사 숫자·패턴 시간 검사 통과. 원본 29개 PCM16/mono·비무음·길이·대본 지문·해시 확인. 정리 행의 CSV 인용 누락을 수정하고 전체 대사 347자·52.84초로 재생성했다. 최종 M4A 세 벌의 ffprobe 길이·상한·SHA256, 필수 시작/정리·확장 질문/해설 짝 검사 통과. 상세는 `report.json`이다. 기술 검사는 발음·억양·내용의 사람 승인을 의미하지 않는다.

대본은 `team/a/lessons/음악-박과리듬.csv`, 확장 18조각은 `음악-박과리듬-확장.csv`, 설계·개념 근거는 `음악-박과리듬-수업안.md`다. 기존 B22 화음 수업과 별개로 제작했다. 앱 담당 후속: 목록에 넣을지 정한 뒤 시간 선택에 맞는 완성판을 연결하거나 원본과 제작표를 이용해 조각 방식으로 통합하고 앱에서 확인한다. 기존 앱 파일은 이번 제작에서 변경하지 않았다.
