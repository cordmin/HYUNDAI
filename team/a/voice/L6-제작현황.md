# L6 짧은 판 음원 최종 납품 기록

2026-11-03. 사용자 지시로 J2 동백꽃과 T8 AI 짧은 판 대본을 직접 작성하고 Nika 음원 각11개, 총22개를 제작했다. T8 대본 미수령 대기 상태는 해소했다. J2·T8 초안 납품과 L6 음원 생산은 완료다. 사람 교사 검수·청취·앱 통합은 후속이며 완료로 표시하지 않는다. 업무표의 담당자를 바꾸지 않는다.

## 검사

- 현재 대본 지문과 원본 WAV 해시 일치, 11/11씩 최신 테이크 확인.
- PCM16/mono·길이·비무음 검사, AAC M4A 변환과 실측 길이 비교 통과.
- 실제 앱 파서·조립기를 읽기 전용 호출한 규격 검사와 선택8조합, 오~구 분 조립 통과. 결과: 동백꽃-짧은판-조립검사.json, 인공지능-짧은판-조립검사.json.
- 납품 묶음마다 현재 WAV11·메타데이터11·M4A11·영수증11·대본·제작메모·인계서·조립검사·음원길이·report.json, 총50파일. 이전 테이크나 테스트용 인공음은 포함하지 않는다.
- 테스트: python team/a/voice/test_short_lesson_tts.py, python -m unittest discover -s tools -p test_lesson_voice_export.py, node team/a/voice/check_short_lesson.js ai 및 dongbaek 통과.
- 사람 교사 검수·사람 청취 승인을 의미하지 않는다. 기존 L4 인공지능22개 청취 완료를 새11개에 확대하지 않는다.

## 앱 담당 인계

1. 각 CSV의 m1~m11을 기존 lessons/동백꽃.csv 및 인공지능.csv에 추가한다. 동백꽃의 다른 컴퓨터 J2안(686e750)과 이번 제작본은 별개이므로 섞지 않는다. J1의 기존36조각 수정안은 이번에 적용하지 않았다.
2. 각 m4a 폴더의 파일11개씩을 앱 voices/lesson에 넣는다. 기존 음원과 이름이 겹치지 않는다.
3. 기존 Measure-Lesson-Voice.ps1로 길이를 재고 빌드한다. 납품용 음원길이.csv는 추가할22개 참고 자료이며 기존 실측 표를 통째로 대체하지 않는다.
4. 실제 앱 반영·교사 검수·사람 청취는 후속 진행한다. 대본을 고치면 해당 음원을 다시 만든다.

현재 앱은 기존89개 그대로다. 납품자료를 합치면89+22=111개지만 앱에111개가 들어갔다고 기록하지 않는다.

기존 앱 조립기는 선택 조각을 추가할 때 도착여유20초를 별도로 빼지 않는다. 동백꽃6분 선택은4.64초, AI5분 선택은17.32초만 남는다. 필수조각만으로는20초 여유를 충족하지만 선택조각 추가 뒤에는 보장하지 않는 기존 규칙의 한계다. 앱 담당에게 인계하며 이 작업에서는 앱 코드를 수정하지 않았다.
