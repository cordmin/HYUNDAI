# 같은 네 박인데, 왜 느낌이 달라질까?

작성: 2026-11-06. 사용자 요청으로 만든 신규 음악 수업 초안. 초등 고학년~중학생과 가족 청취를 가정했다. 기존 B22 「왜 어떤 소리는 어울릴까」와는 다른 수업이며 그 업무를 완료한 것으로 처리하지 않는다.

- 핵심 질문: 같은 네 박인데 왜 다르게 들릴까?
- 목표: 박·템포·리듬을 구별하고, 쉼도 시간이 있는 음악의 일부임을 설명한다.
- 형태: 짧은 판 11조각, 필수 8·선택 3. 추가 18조각은 `음악-박과리듬-확장.csv`에 있다. 8·15·20분은 사용 가능한 시간의 상한이며, 실제 길이와 조립 결과는 `team/a/voice/delivery/music-rhythm/report.json`에 기록한다.
- 대본: `team/a/lessons/음악-박과리듬.csv`. 숙제는 도착 후 가족과 네 박 리듬 하나 만들고 쉼의 위치 설명하기.
- 흐름: 질문 → 일정한 박 → 같은 박 위의 두 리듬 → 이해 발문 → 템포와 리듬 → 쉼 → 분석 발문 → 해설 → 비교 조건 → 창작 발문 → 정리.

## 듣는 예시 제작 지시

말로만 리듬을 설명하는 한계를 보완하도록 m2·m3·m6과 확장 설명에 직접 합성한 예시를 붙인다. 아래 표는 제작 지시이며 CSV 대사에 읽어 넣지 않는다. TTS로 말한 「따따」만으로 정확한 길이를 표현했다고 간주하지 않는다.

공통: 분당 80박, 한 박 0.75초, 네 박 3초. 같은 짧은 합성 타악기 음색·음량을 쓴다. 각 예시를 두 번 반복하고 앞뒤 1초 여유를 둔다. e5는 템포 비교용 60·100박, e6은 길게 잇기 비교, e11~e13은 강세 비교다. 알려진 곡의 음원·가사·선율을 사용하지 않고 단순 패턴을 직접 만든다.

| 예시 | 박 위치(첫 박=0) | 네 박 안에서 소리 시작 시각 | 넣을 곳 |
|---|---|---|---|
| P: 기준 박 | 0, 1, 2, 3 | 0, 0.75, 1.50, 2.25초 | m2 설명 뒤 |
| A: 한 박 한 번 | 0, 1, 2, 3 | 0, 0.75, 1.50, 2.25초 | m3 첫 번째 설명 뒤 |
| B: 첫 박 나누기 | 0, 0.5, 1, 2, 3 | 0, 0.375, 0.75, 1.50, 2.25초 | m3 두 번째 설명 뒤 |
| C: 둘째 박 쉬기 | 0, 2, 3 | 0, 1.50, 2.25초 | m6 설명 뒤 |

각 패턴은 마지막 소리 이후에도 전체 네 박을 채운다. 예시는 해당 조각의 설명 뒤에 차례로 들려준다. e1·e2에서는 낮은 기준 박과 높은 리듬 소리를 겹쳐 비교하며, 다른 조각에서는 패턴만 들려준다. 설명과 예시를 겹치지 않는다. 운전자에게 박수·발 구르기·눈 감기·화면 확인을 요구하지 않는다.

## 개념 근거

- [Classics for Kids, Grieg 수업안(3–5학년)](https://classicsforkids.com/wp-content/uploads/2023/09/Grieg-Lesson-Plans-3-5.pdf): 일정한 박과 리듬을 따로 맡아 함께 표현하는 교육 활동. 본 수업은 차량 환경에 맞게 신체 활동 대신 듣기 비교로 새로 구성했다.
- [Classics for Kids, Beethoven 수업안(K–2)](https://classicsforkids.com/wp-content/uploads/2023/09/Beethoven-Lesson-Plans-K-2.pdf): 네 박 안에 서로 다른 음가를 놓아 리듬을 만드는 활동. 학년 표시는 원자료의 대상이며 본 초안의 교육과정 적합성 승인 근거는 아니다.
- 위 자료의 대본·곡·악보를 복사하지 않았다. 예시와 질문은 직접 작성했다. 음악의 감정 효과를 하나의 정답으로 단정하지 않고, 모든 음악의 박이 일정하다고 일반화하지 않았다.

## 제작 상태와 인계

제작 명령은 `python team/a/voice/music_tts.py`이며 기존 Nika 모델·스타일·인증키 조회·잠금·요청 간격·해시 캐시를 재사용한다. API 없이 재조립하려면 `--export-only`, CSV와 패턴 시간 검사만 하려면 `--check-only`를 쓴다. 짧은 판과 확장판 대본을 조합해 시간 상한 안에 드는 M4A 세 벌과 각 판의 CSV를 만든다. 시간을 초과하면 확장 설명을 묶음 단위로 빼며 질문과 해설은 함께 남긴다. 임의의 긴 무음이나 발화 속도 변경으로 시간을 채우지 않는다.

검사는 CSV 열 수·중복·대사 숫자·패턴 프레임 수·대본 지문·PCM16/mono·길이·비무음·해시·판별 상한을 확인한다. 초안 정리 행의 쉼표 인용 누락을 발견해 수정했으며 그 행의 잘못된 음원은 최신본으로 쓰지 않는다. 사람 교사 검수·음원 청취는 후속이다. 같은 날 앱에 통합했으며 앱 조립 결과는 `team/a/voice/delivery/music-rhythm/앱-통합.md`를 따른다. 대본 변경 시 해당 음원을 다시 만든다. 현재 앱 목록·다른 담당자의 업무·기존 로컬 변경 파일은 수정하지 않는다. 최종 납품 상태는 납품 폴더 README와 검사표를 따른다.
