# 다잇(DAIT) — 차 안에서 학교와 가정을 잇다

등하굣길 남은 시간에 맞춰 오늘의 학교 준비를 짧게 들려주고, 아이의 학교생활을 가족의 대화로 잇는 차량용 교육 메이트입니다.

현대자동차그룹 차량용 앱 개발 공모전(Pleos App Market) 출품을 준비하는 저장소입니다. 서비스 기획은 [`DAIT-기획안.md`](DAIT-기획안.md)에 접수양식 순서대로 정리되어 있습니다.

## 현재 구현 상태 (2026-11-01)

| 기능 | 상태 | 설명 |
|---|---|---|
| Pleos Connect Emulator 실행 | 구현 | Pleos Connect 2.1.0(Android 14, API 34)에 설치·실행 확인 |
| 주행 제한 처리 | 구현 | 앱에 주행 중 사용 선언(`distractionOptimized`)을 넣어, 시뮬레이터로 차를 시속 141km까지 움직여도 앱이 막히지 않음(선언 전에는 「주행 중에는 사용할 수 없습니다」로 앱 전체가 막힘). `CarUxRestrictionsManager`로 주행 제한 상태를 받아 대화 중이면 문장 하나와 큰 버튼 둘(다시 듣기·넘기기)만 있는 주행 화면으로 바꾸고 음성은 이어 감. 대화 중이 아니면 「등교 이야기를 들을까요?」와 「듣기」 버튼을 보여 주고, 주말에는 「주차 후 이어갈게요」를 보여 줌. 실제 주행 중에는 시연 조작 버튼도 숨김. 차 상태를 받기 전이나 받지 못하면 주행 중으로 둠. 실제 차에서의 허용 범위는 Pleos 확인 필요 |
| 앱 화면 | 시연 | WebView로 띄운 `dait-preview.html`. 화면 기준은 Pleos 네이버앱 수준의 레이아웃과 글 양(`design/화면-기준-플레오스.md`). 첫 화면은 '지금 여정'을 판단해 보여 줌: 내비 목적지가 학교면 등교, 집이면 하교, 수업일 오전·오후면 그에 맞게, 주말이면 다음 수업일 준비. 위쪽에 한 문장과 짧은 설명, 아래에 작은 카드 여섯 장(대화 시작, 어디로와 남은 시간·「출발하면 듣기」 버튼, 준비물, 시간표, 점심, 오늘의 질문과 다른 여정 대화). 준비물·점심·시간표는 핵심 단어를 크게 보여 주고, 시간표는 과목 이름을 두 글자로 줄임. 쉬는 날에는 어디로 카드 자리에 가 볼 만한 곳을 보여 줌. 학교를 등록하기 전에는 가짜 내용 대신 등록 안내와 「예시로 듣기」를 보여 줌. 대화 시작 카드의 색이 여정에 따라 바뀜(등교 파랑·보라, 하교 노을빛, 주말 보라). 아침에 고른 과목을 기기에 남겨 하교 첫 말에 그 과목을 다시 묻고(체육은 활동 질문, 나머지는 「아침에 고른 ○○ 시간은 어땠어요?」), '쉬고 싶어'라고 하면 그날은 다시 묻지 않음. 수업이 없는 날은 다음 수업일 준비를 말함 |
| 여정 규칙 | 구현 | `dait-journey.js` 한 곳에서 대화 단계, 남은 시간별 분량(10분 이상 끝까지, 5~10분 짧은 질문까지, 2~5분 준비 안내 하나, 2분 이하 마무리), 아이의 말 해석을 판단함. 화면 없이 시험 81개로 확인. 화면 코드가 끝까지 실행되는지도 함께 시험함 |
| 교사 규칙표 | 구현(초안) | `rules/교사규칙표.csv`를 엑셀로 고치면 앱의 말과 첫 화면이 바뀜(`rules/사용법.md`). 시험 앞둔 기간·전날·당일·마지막 날, 체험학습, 체육대회, 축제, 방학식, 개학 등 대화 규칙 24개와 과목별 오늘의 질문 10개. 대사는 교사 검토 전 초안이고, 음성은 Windows 한국어 음성으로 만든 임시본 |
| 출발하면 듣기 | 구현 | 주차 중 보호자가 누르면 30분 안에 출발할 때 대화를 시작함. 시동만으로는 시작하지 않음. 앱이 학교나 집의 좌표를 알면 버튼이 「학교로 안내」로 바뀌어 한 번에 길 안내까지 시작함. 좌표는 내비로 그곳에 간 적이 있거나 내비의 즐겨찾기·최근 목적지에 있으면 알게 되고, 내비의 「집」 즐겨찾기는 집으로 자동 등록함 |
| 내릴 때 한마디 | 구현 | Pleos Vehicle SDK 2.3.2로 조수석과 뒷좌석 문 상태를 받음. 실제로 달린 여정 뒤 주차한 상태에서 문이 처음 열리면 「내리기 전에 가방이랑 준비물 한 번만 확인해요」를 한 번만 말함. 주차 후 5분이 지나면 말하지 않음. 운전석 문은 보지 않음 |
| 다니는 길 기억 | 구현 | 학교 설정에서 보호자가 켰을 때만 동작(처음에는 꺼짐). 목적지가 학교도 집도 아닐 때, 오전 9시 30분이 지나 학교에 있거나 학교에서 출발하면 하교로 보고(내려 준 직후 제외), 같은 곳에서 같은 요일·비슷한 시간에 3번 이상 반복되고 70% 이상 같은 여정이면 그에 맞춰 첫 화면과 주행 화면의 제안을 바꿈. 판단이 없으면 지금처럼 시간대로 판단. 대화를 스스로 시작하지 않음. 좌표와 지나온 길은 남기지 않고 날짜·요일·10분 단위 시간, 집·학교·그 밖 구분, 문 열림만 기기에 60일 남김. 끄면 기록과 지정한 위치를 모두 지우고, 학교나 집을 바꿔도 기록을 지움. 학교·집 좌표는 내비에서 알게 되거나 설정의 「지금 위치를 학교로/집으로」로 정하고, 직접 정한 좌표는 이 기기에 저장함. 켜기 전에 남기는 내용을 먼저 보여 줌. 위치는 앱이 앞에 있거나 대화 중일 때만 받고, 1분 넘게 끊기면 옛 위치를 쓰지 않으며, 그동안은 내비 도착 신호로 도착지를 알아냄. Pleos FusedLocation이 '준비 중'이라 안드로이드 기본 위치를 쓰고(`LocationBridge.kt`), 위치 권한 승인과 실제 차는 확인 안 함 |
| 내비 뒤에서 이어 가기 | 구현 | 내비가 앱을 덮어도 앞쪽 작업(`JourneyService`)으로 앱을 유지해 말하고 들음. 대화가 끝나면 스스로 내려감 |
| 음성 안내 | 시연 | 사전 제작 음원 51개(`assets/voices/nika`)를 `VoiceSession`이 앱 안에서 재생. 길 안내나 통화가 소리를 가져가면 멈췄다가 돌아오면 그 문장을 처음부터 다시 말하고, 음악처럼 돌려주지 않으면 끼어들지 않고 대화를 마침. 첫 질문 앞에 조각 음원을 이어 붙여 남은 시간과 오늘 시간표를 말함(「학교까지 12분 남았어요. 오늘은 도덕, 국어, 과학, 체육 수업이 있어요」). 수업이 없는 날은 다음 수업일을 알려 주고 묻지는 않음. 조각과 규칙 대사는 아직 임시 음성. Pleos TextToSpeech SDK는 현재 '준비 중' |
| 음성 인식 | 구현 | 오픈소스 Vosk로 기기 안에서 인식해 아이의 답으로 대화가 이어짐. 녹음 파일과 인식한 말은 저장하지 않음. 듣는 동안 화면에 「듣고 있어요」를 표시하고, 학교 설정에서 「말로 답하기」와 「질문」을 끌 수 있고, 질문을 끄면 등교에는 준비 안내만 하고 하교에는 조용히 감. 답이 없으면 한 번 되묻고 조용히 멈춤. 마이크를 쓸 수 없으면 주행 중에는 8초 뒤 다음 단계로 넘어가고, 주차 중에는 답 버튼을 씀. 모델 파일은 용량 때문에 저장소에 없음(아래 설정 참고). Pleos SpeechToText SDK는 현재 '준비 중' |
| 학교 정보(나이스) | 구현(일부) | 주차 중 '학교 설정'에서 학교·학년·반을 고르면 앞으로 7일의 시간표와 점심을 받아 기기에 저장하고, 통신이 끊기면 저장본을 씀. 초등·중·고 모두 검색되며 학교급에 맞는 시간표 창구(`elsTimetable`·`misTimetable`·`hisTimetable`)를 씀. 학사일정은 앞으로 45일치를 받아 우리 학년 일정만 저장함. 시험 날처럼 시간표가 없어도 수업일로 봄. 앱을 열 때만 받음. 학교를 등록하기 전에는 등록 안내를 표시 |
| 가 볼 만한 곳(한국관광공사) | 구현(인증키 대기) | 주차 중 첫 화면의 '가 볼 만한 곳'에서 과학관·박물관·유적지·체험관을 고르면 학교가 있는 시도에서 찾음. 학교가 없으면 전국에서 찾음. 숙박·식당·쇼핑은 뺌. 실제 응답은 인증키를 넣은 뒤 확인해야 함. 브라우저 미리보기는 예시를 보여 줌 |
| 준비물 | 시연 | 나이스에 준비물 항목이 없음. 시간표에 체육이 있으면 체육복 확인을 안내하고, 없으면 학교 안내를 확인하라고 표시 |
| 목적지·남은 시간(NaviHelper) | 구현(일부) | `NaviBridge`가 Pleos NaviHelper SDK 3.0.5에 연결해 길 안내 중 10초마다 목적지 이름과 남은 시간(초)·거리(m)를 받음. 남은 시간에 따라 대화 분량을 줄이고, 2분 이하가 되면 말하던 문장을 마친 뒤 새 질문 없이 마무리함. 도착 신호가 오면 인사하고 첫 화면으로 돌아감. 에뮬레이터 내비는 남은 시간이 줄지 않아 실제 도착 신호로는 시험하지 못했고, 시험용 신호로 확인함. 목적지 이름이나 도로명 주소가 등록한 학교와 같으면 첫 화면이 등교 여정으로, 보호자가 학교 설정의 '지금 목적지를 집으로'로 등록했거나 내비의 집 즐겨찾기인 곳이면 하교 여정으로 바뀜. 이 버튼은 길 안내 중 학교가 아닌 목적지가 있을 때만 보이며, 설정 화면을 먼저 열어 두었다면 다음 내비 응답(최대 10초) 뒤에 나타남. 실제 값이 오면 시연 조작(8분 전·4분 전·2분 전)은 잠김. 목적지 조작은 브라우저 미리보기 전용. 길 안내가 없을 때는 시연 조작을 씀 |

제출 전에 남은 확인 항목은 [`DAIT-기획안.md`](DAIT-기획안.md) 부록 B에 있습니다.

## 실행 방법

Windows PowerShell 기준입니다.

```powershell
# 1. Pleos 에뮬레이터 실행 (더블 클릭 가능)
.\run_pleos.bat
# 또는
powershell -ExecutionPolicy Bypass -File .\tools\Start-Pleos.ps1

# 2. 빌드, 단위 테스트, lint 후 에뮬레이터에 설치
powershell -ExecutionPolicy Bypass -File .\tools\Build-App.ps1 -Install

# 3. 브라우저에서 화면만 미리 보기 (더블 클릭 가능)
.\run_preview.bat
```

단위 테스트만 실행하려면 `android` 폴더에서 `gradlew.bat :app:testDebugUnitTest`를 실행합니다. 여정 규칙 시험은 저장소 맨 위 폴더에서 `node --test android/app/src/test/js/journey.test.js`로 실행합니다.

```powershell
# 4. 에뮬레이터 안에서 음성 인식과 길 안내 양보까지 시험
powershell -ExecutionPolicy Bypass -File .\tools\Build-App.ps1 -Install -DeviceChecks
```

주행 상태는 Virtual Console로 만듭니다. `adb -s emulator-5554 forward tcp:8088 tcp:8088`을 실행한 뒤 `http://127.0.0.1:8088/`을 열고 기어를 D로 바꾼 다음 ACCEL을 누르고 있으면 차가 움직입니다. Pleos 문서의 `hmg_car_service` 명령은 이 에뮬레이터에 없습니다.

| 항목 | 값 |
|---|---|
| 플랫폼 | Android Automotive OS, Pleos Connect Emulator 2.1.0 (Android 14 / API 34, RAM 4GB, Cold boot) |
| 가상 기기 이름 | `DAIT_Pleos_2_1` 또는 `Automotive_1408p_landscape` (둘 다 Pleos 이미지. `Build-App.ps1`은 둘 다 받고, `run_pleos.bat`과 `Start-Pleos.ps1`은 `DAIT_Pleos_2_1`만 켬) |
| 빌드 | JBR 21, Gradle 8.7, AGP 8.5.2, Kotlin 1.9.24, compileSdk 34, minSdk 28. Pleos SDK 저장소(`nexus-playground.pleos.ai`)에서 NaviHelper와 Vehicle을 받으므로 첫 빌드에 인터넷이 필요 |
| 빌드 스크립트 전제 | `Build-App.ps1`은 JDK를 `%USERPROFILE%\.jdks\jbr-21.0.11`에서 찾고, 에뮬레이터를 `emulator-5554`로 가정함. 다른 PC에서는 이 두 값을 맞춤 |
| 패키지명 | `io.dait.app` |
| 마이크 | 음성 인식을 시험하려면 Virtual Console에서 마이크 접근을 허용 |
| 인증키 | 앱과 브라우저 미리보기는 중계 서버 `https://relay-khaki-omega.vercel.app`을 거쳐 자료를 받으므로 팀원과 이용자에게 키가 필요 없음. 키는 Vercel의 `relay` 프로젝트 환경 변수(`NEIS_API_KEY`, `TOUR_API_KEY`)에만 두고, 바꾼 뒤에는 `npx.cmd vercel deploy --prod --yes --cwd relay`로 다시 올림 |
| 관광공사 인증키 | [공공데이터포털](https://www.data.go.kr/data/15101578/openapi.do)에서 활용신청 후 받은 일반 인증키를 위 환경 변수에 넣음. 키가 없으면 앱은 '지금은 찾을 수 없어요'를 표시 |
| 음성 인식 모델 | `py -I tools\Setup-Voice-Model.py`를 실행하면 Vosk 한국어 모델(내려받기 약 87MB)을 받아 `android/app/src/main/assets/model-ko/`에 둠. 용량 때문에 저장소에서 제외. 모델 없이 빌드해도 앱은 동작하지만 답은 터치로만 받음 |
| 마이크 허락 | 처음 대화를 시작하거나 「출발하면 듣기」를 누를 때 주차 중에 한 번 물음 |
| 위치 허락 | 학교 설정에서 「다니는 길 기억」을 켤 때 한 번 물음. 정확한 위치를 허락해야 켜짐. 에뮬레이터에서는 `adb emu geo fix 경도 위도`로 위치를 넣어 시험 |

설치 과정과 점검 결과는 [`개발환경-점검.md`](개발환경-점검.md)에 있습니다.

## APK 위치

- 개발용: `apk/DAIT-dialogue-debug.apk` (debug 빌드, 저장소에는 올리지 않음)
- 제출용: `powershell -ExecutionPolicy Bypass -File .\tools\Build-App.ps1 -Release -TeamName 팀명`을 실행하면 `apk/팀명_다잇_release.apk`가 만들어집니다(음성 모델 포함 약 160MB). 서명 키는 PC마다 `tools\Make-Release-Key.ps1`을 한 번 실행해 만들고 저장소에는 올리지 않습니다. 키는 `%USERPROFILE%\.dait\`에, 비밀번호는 `android/keystore.properties`에 있습니다. 키를 잃으면 같은 앱으로 덮어 설치할 수 없습니다.
- 공모전 제출 형식: `apk/팀명_앱이름_release.apk`. GitHub는 저장소에 100MB가 넘는 파일을 올릴 수 없으므로 GitHub Releases에 올리고 그 주소를 제출합니다.

## 검증

- 여정 규칙 시험 81개(`journey.test.js`): 남은 시간 구간, 등교·하교 흐름, 쉬기, 도착 임박 마무리, 말 해석, 교사 규칙 고르기, 다니는 길 기억. 에뮬레이터 음성 인식이 실제로 낸 결과와 실제 학교의 학사일정도 그대로 넣어 확인합니다. Kotlin 단위 테스트는 나이스·관광공사 호출 주소를 검사합니다.
- 2026-11-01 Pleos 에뮬레이터 2.1.0(가상 기기 `Automotive_1408p_landscape`, 앱 창 665×420)에서 Virtual Console로 기어 D와 가속을 넣어 차를 실제로 움직이며 확인했습니다.
  - 선언 전에는 시속 16km에서 앱 전체가 막혔고, 선언 후에는 시속 141km에서도 주행 화면이 떴습니다.
  - 내비가 앱을 덮은 채 출발하자 예약한 대화가 시작되어 음원이 끝까지 나왔고, 듣기 단계에서 시스템이 마이크를 막지 않았습니다(`rec start … not silenced`). 답이 없자 잡음으로 재촉하지 않고 한 번 되물은 뒤 조용히 마쳤고 앞쪽 작업도 내려갔습니다.
  - 길 안내와 같은 방식으로 소리를 가져가는 시험에서 멈춤, 재개, 완료가 차례로 일어났습니다(`-DeviceChecks`). 에뮬레이터 내비는 안내 음성을 내지 않아 실제 안내 음성과 겹쳐 시험하지는 못했습니다.
  - 음성 인식은 시험용 합성 음성으로 「응 체육복 챙겼 어」, 「아직 안 챙겼 어」, 「과학」을 맞혔고, 관계없는 말은 받지 않았습니다. 사람이 마이크에 직접 말하는 시험과 아이 목소리, 차 소음 환경은 확인 안 함입니다.
  - 다니는 길 기억: Pleos 에뮬레이터에서 위치 허락 창, 시험용 위치 수신, 집과 학교 구분, 학교 앞 문 열림으로 등교 기록, 앞쪽 작업에 위치 포함을 확인했습니다. 차의 이동과 문 열림은 시험용으로 넣었고, 실제 차와 실제 주행은 확인 안 함입니다.
  - 등교 전체, 말하고 싶지 않은 날, 남은 시간별 분량, 도착, 속상한 날 다섯 장면과, 늦게 온 알림, 달리는 중 대화 종료, 마이크 실패, 음악이 소리를 가져간 경우, 도착 신호 없는 안내 종료를 앱 안에서 돌렸습니다. 음성·화면·판단은 실제이고 아이의 말과 내비 값은 시험용으로 넣었습니다.
  - 학교를 등록한 앱에서 중계 서버로 실제 시간표, 점심, 학사일정을 받았습니다(중학교 한 곳).
  - 앱이 Pleos NaviHelper로 길 안내를 요청하자 내비가 앞으로 나오며 안내를 시작했고(3.1km·660초), 내비가 안내하는 동안 다잇이 뒤에서 남은 시간을 받아 등교 대화를 끝까지 진행했습니다.
  - Virtual Console로 뒷문을 열어, 여정 전에는 말하지 않고 달린 뒤 주차해서 열면 한 번만 말하는 것을 확인했습니다.
  - 그 학교의 실제 일정(2차 시험 3일, 축제)에 날짜를 맞춰 시험 앞둔 기간, 전날, 첫날, 마지막 날, 축제의 첫 화면과 대화를 앱에서 확인했습니다. 날짜는 시험용으로 고정했고 아이의 말은 시험용으로 넣었습니다.
- 이전 네이티브 화면 빌드의 설치·주차 상태·음원 재생 기록: `design/앱-실행-검증.md`, `voice/검증.md`.
- 현재 WebView 화면은 Pleos 에뮬레이터 2.1.0(가상 기기 `Automotive_1408p_landscape`, 앱 창 665×420)에 설치해 등교·하교 경로와 '주차/주행 전환' 버튼을 터치로 확인했습니다. 시험한 PC에 SDK 34가 없어 임시 복사본을 compileSdk 35로 빌드했습니다.
- 첫 화면 재설계는 브라우저 미리보기에서 등교·하교·주말·학교 등록 전 네 상태와 창 크기 3가지(1280×720, 665×420, 420×640)에서 잘림 없음을 확인했습니다. 대화, 학교 설정, 가 볼 만한 곳, 주행 화면은 665×420에서 확인했습니다. 떠다니는 장식은 두지 않습니다.
- 목적지 판단은 브라우저 미리보기에서 학교 이름 일치, 도로명 주소 일치, 집 등록, 무관한 목적지, 길 안내 취소를 확인했습니다. 실제 내비로는 에뮬레이터에서 서울시청을 집으로 등록해 확인했습니다.
- 내비 연결은 Pleos 에뮬레이터에서 확인했습니다. 시험용 호출로 길 안내(판교→서울시청)를 시작하자 앱이 1740초·26000m를 받았고 내비 앱 화면의 29분·26km와 일치했습니다. 길 안내가 없을 때는 빈 값이 와서 화면이 무시합니다. 실제 차에서는 확인 안 함.
- 주행 화면 전환, 아침 과목을 하교에 잇기, 2분 전 마무리, 넘기기는 브라우저 미리보기에서 23개 경로를 확인했습니다.
- 학교급 확장은 브라우저 미리보기에서 초등(경기)·중학교(전남)·고등학교(전남) 각 한 곳으로 확인했습니다.
- 나이스 연결은 같은 에뮬레이터에서 인증키를 넣고 빌드해 확인했습니다. 한 주 시간표 27건이 모두 왔고 6교시가 있는 날도 6과목이 표시됩니다. 키 없이 빌드하면 하루 5건까지만 옵니다. 학교 검색부터 시간표·점심 표시까지 터치로 진행했고, 인터넷을 끊고 앱을 다시 켜도 저장본이 표시됩니다.
- 음원을 사람이 귀로 듣는 확인은 하지 않았습니다. 실제 차에서는 시험하지 않았습니다. `DAIT_Pleos_2_1`에서는 아직 실행하지 않았습니다.
- 에뮬레이터 부팅 직후 부하가 높으면 앱이 응답 없음으로 꺼질 수 있습니다. 부하가 내려간 뒤에는 수정 전 화면과 현재 화면 모두 정상이었습니다.
- 제출용 앱을 지운 뒤 새로 설치해 학교 등록 안내, 마이크 허락, 음성, 듣기, 답 버튼, 내비 연결, 시속 52km 주행 화면을 터치로 확인했습니다(`design/device-screen.png`).
